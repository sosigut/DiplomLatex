\subsubsection{TC-01. Проверка корректного DOCX-документа}

\textbf{Предусловие:} сервер запущен, пользователь авторизован.

\textbf{Шаги:}
\begin{enumerate}
	\item Отправить POST-запрос на \texttt{/checker/check} с корректным DOCX-файлом и параметром \texttt{doc\_type=manual}.
	\item Дождаться завершения проверки.
\end{enumerate}

\textbf{Ожидаемый результат}: в ответе поле \texttt{has\_errors: false}, документ сохраняется в базе данных. PDF-отчёт не формируется.

\textbf{Фактический результат}: пройден.

\subsubsection{TC-02. Проверка документа с ошибками оформления}

\textbf{Предусловие:} сервер запущен, пользователь авторизован.

\textbf{Шаги:}
\begin{enumerate}
	\item Отправить POST-запрос на \texttt{/checker/check} с DOCX-файлом, содержащим нарушения оформления (неверный шрифт, отсутствие отступа).
	\item Дождаться завершения проверки.
\end{enumerate}

\textbf{Ожидаемый результат}: в ответе поле \texttt{has\_errors: true}. Формируются:
\begin{itemize}
	\item исправленная копия DOCX с выделением ошибок красным цветом;
	\item PDF-отчёт с таблицей ошибок (номер, тип, местоположение, описание);
	\item ссылки на оба файла возвращаются клиенту.
\end{itemize}

\textbf{Фактический результат}: пройден.

\subsubsection{Нефункциональное тестирование}

Помимо функциональных тестов, были проверены нефункциональные требования, описанные в техническом задании.

\textbf{Быстродействие}: проверка DOCX-документов объёмом до 100 страниц выполняется не более чем за 120 секунд. Генерация титульного листа занимает не более 5 секунд. Формирование PDF-отчёта завершается менее чем за 3 секунды.

\textbf{Совместимость с браузерами}: клиентская часть протестирована в браузерах Google Chrome, Mozilla Firefox, Yandex. Во всех браузерах корректно работают загрузка файлов, drag-and-drop, динамические формы и скачивание файлов.

\textbf{Надёжность}: при разрыве соединения с базой данных сервер возвращает HTTP-статус 500. При ошибках COM-интерфейса Word система корректно завершает процесс и очищает временные файлы. Транзакционное сохранение проверенных документов гарантирует целостность данных.

\textbf{Безопасность}: доступ к защищённым маршрутам предоставляется только при наличии валидного JWT-токена. Пароли пользователей хранятся в хешированном виде (Argon2). Административные функции доступны только пользователям с соответствующей ролью.

Все нефункциональные требования выполнены в полном объёме.
