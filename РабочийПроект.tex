\subsection{Системное тестирование разработанного web-сайта}

В процессе разработки было проведено функциональное тестирование ключевых компонентов бэкенда: проверки документов, генерации титульных листов и отправки в РИО. Тестирование выполнялось с использованием инструментов (FastAPI, Postman) и проверки выходных данных (DOCX, PDF, email).

\subsubsection{Тестирование модуля проверки документов}

\textbf{Сценарий 1: Проверка документа, соответствующего требованиям.}

\begin{itemize}
	\item \textbf{Входные данные}: DOCX-файл методических указаний, оформленный по ГОСТ (шрифт Times New Roman, размер 16 pt, отступы 1,25 см, одинарный интервал).
	\item \textbf{Действие}: Отправка POST-запроса на \texttt{/checker/check}.
	\item \textbf{Ожидаемый результат}: Система через COM-интерфейс Word выполняет проверку, не находит ошибок. В ответе \texttt{has\_errors: false}, документ автоматически сохраняется в БД. PDF-отчёт не формируется.
\end{itemize}

\textbf{Сценарий 2: Проверка документа с ошибками оформления.}

\begin{itemize}
	\item \textbf{Входные данные}: DOCX-файл с намеренными нарушениями (шрифт Arial, размер 12 pt, отсутствие отступа).
	\item \textbf{Действие}: Отправка POST-запроса на \texttt{/checker/check}.
	\item \textbf{Ожидаемый результат}: Алгоритм проверки выявляет ошибки, фиксирует номера страниц и группирует их в диапазоны. В ответе \texttt{has\_errors: true}, формируются:
	\begin{itemize}
		\item исправленная копия DOCX с выделением ошибок красным цветом и комментариями;
		\item PDF-отчёт с таблицей ошибок (номер, тип, местоположение, описание);
		\item ссылки на оба файла возвращаются клиенту.
	\end{itemize}
\end{itemize}

\subsubsection{Тестирование модуля генерации титульных листов}

\textbf{Сценарий 1: Генерация титульного листа для методических указаний.}

\begin{itemize}
	\item \textbf{Входные данные}: JSON с полями: \texttt{manual\_title}, \texttt{discipline\_name}, \texttt{direction\_code}, \texttt{compiler\_name}, \texttt{reviewers} (массив), \texttt{udk}, \texttt{description}.
	\item \textbf{Действие}: Отправка POST-запроса на \texttt{/title-page/generate}.
	\item \textbf{Ожидаемый результат}: Библиотека \texttt{python-docx} формирует DOCX-файл с двумя страницами, соответствующими шаблону (шапка, блок утверждения, название, дисциплина, выходные данные, УДК, рецензенты, аннотация). Файл возвращается клиенту.
\end{itemize}

\textbf{Сценарий 2: Генерация титульного листа для монографии.}

\begin{itemize}
	\item \textbf{Входные данные}: JSON с полями: \texttt{authors} (массив), \texttt{monograph\_title}, \texttt{city}, \texttt{year}, \texttt{udk}, \texttt{bbk}, \texttt{isbn}, \texttt{description}.
	\item \textbf{Действие}: Отправка POST-запроса на \texttt{/title-page/generate-monograph}.
	\item \textbf{Ожидаемый результат}: Формируется DOCX-файл, содержащий на первой странице авторов (в одну строку) и название монографии, на второй — УДК, ББК, ISBN, аннотацию и сведения об авторских правах.
\end{itemize}

\subsubsection{Тестирование модуля отправки в РИО}

\textbf{Сценарий 1: Полный успешный цикл отправки.}

\begin{itemize}
	\item \textbf{Шаг 1 (upload-step1)}: POST-запрос с двумя вспомогательными файлами (например, PDF и TXT). Система сохраняет их во временную директорию и возвращает \texttt{next\_step: 2}.
	\item \textbf{Шаг 2 (upload-step2)}: POST-запрос с основным DOCX-файлом. Система запускает проверку через COM-интерфейс. Если ошибок нет, возвращает \texttt{next\_step: 3}.
	\item \textbf{Шаг 3 (submit-step3)}: POST-запрос с JSON-полем \texttt{comment} (до 1000 символов). Система формирует email (тема: «Новые методические материалы от [ФИО]», тело: информация об отправителе и комментарий). Все три файла прикрепляются как вложения. Email отправляется через SMTP. Временные файлы удаляются.
\end{itemize}

\textbf{Сценарий 2: Ошибка на шаге 2 (некорректный файл).}

\begin{itemize}
	\item \textbf{Входные данные}: DOCX-файл с ошибками оформления.
	\item \textbf{Действие}: POST-запрос на \texttt{/rio/upload-step2}.
	\item \textbf{Ожидаемый результат}: Модуль проверки выявляет ошибки, сервер возвращает HTTP-статус 422 и сообщение «В данном документе «имя\_файла» имеются ошибки, выполните полную проверку файла». Переход к шагу 3 блокируется, сессия не изменяется.
\end{itemize}


\subsubsection{Результаты тестирования}

В ходе функционального тестирования было подтверждено, что:
\begin{itemize}
	\item модуль проверки документов корректно анализирует параметры форматирования через COM-интерфейс Word, выявляет ошибки, группирует их по страницам и формирует исправленную копию с визуальным выделением;
	\item модуль генерации титульных листов создаёт DOCX-файлы для трёх типов документов в соответствии с утверждёнными шаблонами;
	\item модуль отправки в РИО обеспечивает надёжное временное хранение файлов и отправку email с вложениями через SMTP.
\end{itemize}

Все ключевые компоненты бэкенда функционируют в соответствии с требованиями технического задания. Система готова к промышленной эксплуатации в редакционно-издательском отделе вуза.
